## S2-078

- **CVE编号:** CVE-2026-104714
- **危害定级:** 中危
- **漏洞标签:** Disclosure of Data, Denial of Service
- **披露日期:** 
- **信息来源:** [https://cwiki.apache.org/confluence/spaces/WW/pages/451972217/S2-078](https://cwiki.apache.org/confluence/spaces/WW/pages/451972217/S2-078)

### 漏洞描述

Struts renders localized messages through an application-wide text provider, which retains the formatter used to render each message. Where a message formats a date or time argument, that retained formatter is used by requests being served concurrently without isolation between them, so two requests rendering the same message at the same time can interfere: a value belonging to one user can appear in another user's response, or the rendering can fail and surface as a server error. Triggering this requires no malicious request — ordinary concurrent traffic is enough, and the users harmed are the application's own.

### 修复方案

Upgrade to Struts 7.4.0 at least.

## WordPress预认证XSS导致RCE漏洞

- **CVE编号:** CVE-2026-64638
- **危害定级:** 高危
- **漏洞标签:** 公开漏洞
- **披露日期:** 2026-08-08
- **信息来源:** [https://www.oscs1024.com/hd/MPS-3zjh-mefr](https://www.oscs1024.com/hd/MPS-3zjh-mefr)

### 漏洞描述

WordPress 是广泛使用的开源内容管理系统，用于建站、内容发布与后台管理。
受影响版本中，用户登录失败时，系统会把提交的用户名直接拼进错误提示并输出到页面，且未做 HTML 转义。用户名虽经过标签剥离处理，但 PHP 的 strip_tags 与 WordPress 自带的 KSES 过滤规则不一致：攻击者可构造“小于号后带空格”的伪标签内容，前者当作普通文本放行，后者却识别为合法 HTML，从而在未登录的登录页注入可控页面元素。登录页默认还会加载本用于个人资料页的脚本，注入内容可驱动该脚本自动发起同站请求，并结合 REST 接口的 JSONP 能力，在站点自身源下执行恶意脚本。若目标为已登录的单站管理员，攻击者还可进一步诱导其完成应用密码授权、发布内容并上传插件压缩包，使服务器上可直接访问插件目录中的 PHP 文件，最终以网站运行账号权限在服务器上执行代码。
修复版本中通过对失败登录回显中的用户名、邮箱等做 HTML 转义（esc_html 等），避免未编码内容进入页面，从源头消除登录页反射型跨站脚本，并阻断后续通向远程代码执行的利用路径。

## Linux 内核 TCP-AO 内存错误引用漏洞(CVE-2026-64459)

- **CVE编号:** CVE-2026-64459
- **危害定级:** 严重
- **漏洞标签:** 关键漏洞, UAF, 影响亿级, TCP-AO
- **披露日期:** 2026-08-17
- **信息来源:** [https://ti.qianxin.com/vulnerability/detail/480780](https://ti.qianxin.com/vulnerability/detail/480780)

### 漏洞描述

在 Linux 内核中，以下漏洞已被修复：

tcp: 在 tcp_ao_destroy_sock 中恢复 RCU 宽限期

提交 51e547e8c89c（"tcp: Free TCP-AO/TCP-MD5 info/keys without RCU"）从 tcp_ao_destroy_sock() 中移除了 call_rcu() 回调，理由是 info/keys 的销毁被延迟到 socket 的析构函数执行时，因此 "no one can discover it anymore"。

这一论点对于 tcp_connect() 中的调用点不成立 (net/ipv4/tcp_output.c:4327-4332)。此时 socket 处于 TCP_SYN_SENT 状态，已经在 tcp_v4_connect() 中被 inet_hash_connect() 插入到 inet ehash，因此它非常容易被发现：任何在其他 CPU 上运行 tcp_v4_rcv() 的软中断都可以将 socket 从 ehash 中取出，进入 tcp_inbound_hash()，并在销毁 CPU 上获取 bh_lock_sock_nested() 之前，通过隐式 RCU 加载 tp->ao_info。

读取路径随后进入 __tcp_ao_do_lookup() (net/ipv4/tcp_ao.c:208)，该函数通过 rcu_dereference_check() 重新加载 tp->ao_info；重新加载仍然可以观察到（即将被释放的）指针，因为在 rcu_assign_pointer(tp->ao_info, NULL) 和 tcp_ao_destroy_sock() 中的 tcp_ao_info_free() 之间没有 synchronize_rcu()。被捕获的指针随后在 223 行被遍历：

	hlist_for_each_entry_rcu(key, &ao->head, node, ...)

写者的同步 kfree() 完全可以在 218 行的重新获取和
223 行的 hlist 迭代之间完成。slab 被重新使用（或者如果尚未被重用则简单地标记为 LIST_POISON1），而迭代在软中断上下文中遍历攻击者控制或已被污染的内存。

复现程序（无调试垫片，标准 x86_64 v7.1-rc2 SMP+KASAN，QEMU+KVM）：一个在 CLONE_NEWUSER|CLONE_NEWNET 内的非特权 uid=1000 进程在 TCP socket 上安装 TCP_MD5SIG + TCP_AO_ADD_KEY，通过 raw sockets 向其最终的 4-tuple 发送伪造的 TCP-AO 段，然后调用 connect()。tcp_connect() 中的 md5-wins 协调触发 tcp_ao_destroy_sock()；回环 NAPI 路径上的软中断 backlog 读取者在遍历已释放的 ao->head.first 时崩溃：

  Oops: general protection fault, probably for non-canonical
    address 0xfbd59c000000002f
  KASAN: maybe wild-memory-access in range
    [0xdead000000000178-0xdead00000000017f]
  CPU: 0 UID: 1000 PID: 100 Comm: repro_userns
  RIP: 0010:__tcp_ao_do_lookup+0x107/0x1c0
  Call Trace: <IRQ>
    __tcp_ao_do_lookup+0x107/0x1c0
    tcp_ao_inbound_lookup.constprop.0+0x12a/0x200
    tcp_inbound_ao_hash+0x5ea/0x1520
    tcp_inbound_hash+0x7ce/0x1240
    tcp_v4_rcv+0x1e7a/0x3e10
    ...

恢复 RCU 宽限期：重新将 struct rcu_head 添加到 tcp_ao_info，并将同步的 tcp_ao_info_free() 替换为 call_rcu() 回调。在 rcu_assign_pointer 将其置为 NULL 之前捕获了 tp->ao_info 的读取者，现在可以看到该对象保持有效直到 rcu_read_unlock()。应用补丁后，复现程序在同一内核构建上干净地运行了 2000 次迭代。

### 漏洞描述

在 Linux 内核中，已修复以下漏洞：

bpf: Fix a UAF issue in bpf_trampoline_link_cgroup_shim

此 bug 的根本原因是当 'bpf_link_put' 将 'shim_link->link.link' 的 refcount 减少到零时，该资源被认为已释放，但仍可能通过 'cgroup_shim_find' 中的 'tr->progs_hlist' 进行引用。在 'bpf_shim_tramp_link_release' 中对 'tr->progs_hlist' 的实际清理被延迟。在此期间，另一个进程可以通过 'bpf_trampoline_link_cgroup_shim' 导致 use-after-free。

修复方法：
   在 'bpf_trampoline_link_cgroup_shim' 中添加一个原子非零检查。
   仅在 refcount 不为零时才递增。

测试：
   我通过在 'bpf_shim_tramp_link_release' 中添加延迟来验证修复，以便更容易触发该 bug：

static void bpf_shim_tramp_link_release(struct bpf_link *link)
{
	/* ... */
	if (!shim_link->trampoline)
		return;

+	msleep(100);
	WARN_ON_ONCE(bpf_trampoline_unlink_prog(&shim_link->link,
		shim_link->trampoline, NULL));
	bpf_trampoline_put(shim_link->trampoline);
}

补丁前，运行 PoC 可轻松复现崩溃（几乎 100%），调用跟踪与 KaiyanM 的报告类似。
补丁后，即使经过数百万次迭代，该 bug 也不再发生。

## OTRS-伪造Remote-User绕过认证漏洞(CVE-2026-93582)

- **危害定级:** 严重

PHP是一款广泛使用的开源服务器端脚本语言，大量网站与应用基于其构建。2026年10月21日，PHP官方发布安全更新，披露其跨请求全局状态管理机制中存在堆内存释放后重用漏洞。PHP worker 进程持有的错误、会话、对象及扩展等全局状态指向仅属于单个请求的堆内存，该状态需在请求内存释放前完成复位；当请求因致命错误（包括内存耗尽、执行超时等）中断而未执行对应的复位，或非致命诊断在请求关闭阶段将请求所属信息重新写入已清理的全局状态时，请求堆内存释放后残留引用仍被 worker 保留，后续请求中先于正常初始化执行的输入、配置、会话及错误处理操作会读取或基于该残留状态进行处理，造成释放后重用。未经身份验证的远程攻击者可构造由同一 worker 先后处理的特制请求触发该漏洞，导致内存信息泄露并以Web进程权限执行任意代码，造成服务器失陷。成功利用要求相关请求由同一 worker 进程先后处理，利用可靠性依赖于 PHP 构建、扩展、前端行为与堆内存布局。受影响版本:8.2.35、8.3.36、8.4.27、8.5.12之前的所有版本(官方补丁仅覆盖8.2-8.5受支持分支,更早版本已停止维护)。该漏洞与CVE-2026-109618同属同一安全事件，漏洞事件跟踪以AVD-2026-109618为主。

PHP < 8.2.35（8.2 分支），升级至 8.2.35 或该分支更新版本。
PHP < 8.3.36（8.3 分支），升级至 8.3.36 或该分支更新版本。
PHP < 8.4.27（8.4 分支），升级至 8.4.27 或该分支更新版本。
PHP < 8.5.12（8.5 分支），升级至 8.5.12 或该分支更新版本。

## Microsoft SharePoint JWT 认证权限绕过漏洞

- **CVE编号:** CVE-2026-55040
- **危害定级:** 高危
- **漏洞标签:** POC已公开
- **披露日期:** 2026-07-14
- **信息来源:** [https://avd.aliyun.com/detail?id=AVD-2026-55040](https://avd.aliyun.com/detail?id=AVD-2026-55040)

### 漏洞描述

Microsoft SharePoint Server 是微软推出的企业级门户与协作平台。2026年7月披露其存在权限绕过漏洞。该漏洞可远程利用，无需权限与用户交互。SharePoint 的服务器间（S2S）认证对 JWT 令牌的校验存在弱认证缺陷，未严格验证令牌签名与来源，未授权的远程攻击者可伪造通过校验的 JWT 令牌，冒充任意站点用户（包括管理员）身份执行操作，读取或篡改站点数据，结合该漏洞簇其他漏洞可进一步实现代码执行，导致服务器失陷。

1. 升级至修复版本：SharePoint Enterprise Server 2016 升级至 16.0.5561.1001 及以上；SharePoint Server 2019 升级至 16.0.10417.20175 及以上；SharePoint Server Subscription Edition 升级至 16.0.19725.20434 及以上。
2. 利用安全组设置其仅对可信地址开放。
3. 为 SharePoint 及 IIS 工作进程启用 AMSI 集成，并将请求体扫描模式设置为 Full。

## Apache ActiveMQ jolokia 代码执行漏洞（CVE-2026-42588）

- **披露日期:** 2026-06-01

### 漏洞描述

Apache ActiveMQ 是一个开源的多协议消息代理服务器。2026年6月，官方披露 CVE-2026-34197 ActiveMQ Jolokia 远程代码执行漏洞。Apache ActiveMQ 在通过 Jolokia 接口处理请求时存在输入校验不当（CWE-20）与代码生成控制不当（CWE-94）缺陷。攻击者可构造恶意请求，在 ActiveMQ Broker 的 JVM 上注入并执行任意代码，从而执行任意命令控制Activemq。
