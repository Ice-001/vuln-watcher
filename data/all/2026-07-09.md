## XWiki Platform 路径遍历漏洞(CVE-2026-34151)

- **CVE编号:** CVE-2026-34151
- **危害定级:** 高危
- **漏洞标签:** 影响万级, 技术细节公开, POC公开, 奇安信CERT验证, 关键漏洞
- **披露日期:** 2026-07-08
- **推送原因:** 漏洞创建
- **信息来源:** [https://ti.qianxin.com/vulnerability/detail/473820](https://ti.qianxin.com/vulnerability/detail/473820)

### 漏洞描述

XWiki 是一款开源的企业级 Wiki 平台和知识管理工具，基于 Java 开发，支持结构化内容管理、文档协作、扩展插件机制以及强大的脚本和宏功能。它广泛应用于团队知识库构建、内部文档共享、企业门户和内容管理系统等领域，提供实时协作编辑、版本控制、权限管理和搜索等核心特性。XWiki 具有高度的可扩展性，可通过插件和脚本实现自定义应用开发，是许多组织数字化知识管理的首选平台。
该漏洞源于 /skin/ action 端点在处理资源路径时，未充分抵御 Jetty 12+ 应用服务器特有的 URL 解码和规范化行为，导致攻击者可通过双重 URL 编码的 “..%252f” 序列绕过路径限制。该漏洞主要影响使用 Jetty 12+ 部署的 XWiki 实例（例如官方 Docker 镜像，默认将 XWiki 部署在多级目录下）。攻击者可利用该漏洞，通过构造特殊 URL 访问 Jetty 实例有权限读取的任意资源，包括系统配置文件、Hibernate 配置、XWiki 配置文件甚至服务器敏感文件（如 /etc/passwd），从而导致敏感信息泄露。

phpBB 是一款基于 PHP 开发的开源互联网论坛软件平台，自2000年发布以来广泛应用于全球各类社区、技术支持、爱好交流及商业客户站点。phpBB 提供了完整的论坛功能，包括用户注册与管理、帖子发布与回复、私信系统、用户组权限管理、主题订阅、附件上传以及多种认证方式（包括数据库认证和 OAuth 认证）等。该软件以其轻量级、高度可定制和易于部署的特点，在2000年代至2010年代初达到流行高峰，至今仍支撑着全球数千个活跃论坛。

## ActiveMQ Jolokia 远程代码执行漏洞

- **CVE编号:** CVE-2026-34197
- **危害定级:** 高危
- **漏洞标签:** 公开漏洞
- **披露日期:** 2026-04-08
- **信息来源:** [https://www.oscs1024.com/hd/MPS-xwyr-fole](https://www.oscs1024.com/hd/MPS-xwyr-fole)

### 漏洞描述

Apache ActiveMQ Classic 是 Apache Software Foundation 开源的 Java 消息中间件，用于构建 JMS 消息代理与系统集成场景。
受影响版本中，Jolokia JMX-HTTP 桥接接口 /api/jolokia/ 在默认策略下允许已认证用户调用 BrokerView 暴露的 addConnector(String) 与 addNetworkConnector(String)，传入恶意 discovery URI 后可经 VM transport 加载远程 Spring XML，且 Bean 实例化发生在 Broker 配置校验前，最终在 Broker JVM 上执行任意代码。
修复版本中通过在 BrokerView.addConnector(String) 和 addNetworkConnector(String) 调用前新增 validateAllowedUrl/validateAllowedUri 校验，禁止 vm scheme 及其嵌套 composite URI 进入底层连接器创建流程，从而阻断远程 Spring XML 加载路径。

### 修复方案

1. 将组件 org.apache.activemq:activemq-broker 升级至 5.19.4 及以上版本
2. 将组件 org.apache.activemq:activemq-all 升级至 6.2.3 及以上版本
3. 将组件 activemq 升级至 5.19.4 及以上版本
4. 将组件 activemq 升级至 6.2.3 及以上版本
5. 将组件 org.apache.activemq:activemq-broker 升级至 6.2.3 及以上版本
6. 将组件 org.apache.activemq:activemq-all 升级至 5.19.4 及以上版本

## MLflow tar解压路径穿越漏洞

### 漏洞描述

## Handlebars < 4.7.9 AST注入RCE漏洞

- **CVE编号:** CVE-2026-33937
- **危害定级:** 严重
- **漏洞标签:** 公开漏洞
- **披露日期:** 2026-03-30
- **信息来源:** [https://www.oscs1024.com/hd/MPS-th3l-nwyq](https://www.oscs1024.com/hd/MPS-th3l-nwyq)

### 漏洞描述

Handlebars 是一个流行的 JavaScript 语义化模板引擎，用于构建动态网页和 Node.js 应用。
受影响版本中，Handlebars.compile() 函数除接受字符串模板外，还接受预解析的 AST 对象作为输入。编译器在将 AST 转换为可执行 JavaScript 函数时，未对 NumberLiteral 节点的 value 字段进行类型校验，直接将该字段内容拼接进生成的 JavaScript 代码字符串。攻击者可构造包含任意字符串（而非数字）的 value 字段，使生成代码中嵌入恶意逻辑，从而在服务端触发任意 JavaScript 代码执行（RCE）。
修复版本中通过在 lib/handlebars/compiler/base.js 新增 validateInputAst() 函数，在编译前对所有 AST 节点字段进行递归类型校验，要求 NumberLiteral.value 必须为有限数字、PathExpression.parts 仅含字符串、BooleanLiteral.value 必须为布尔值，对不合法输入直接抛出异常，从根本上切断注入路径。

### 修复方案

1. 将组件 handlebars 升级至 4.7.9 及以上版本
2. 将组件 node-handlebars 升级至 4.7.9-1 及以上版本
3. 将组件 libjs-handlebars 升级至 4.7.9-1 及以上版本
4. 将组件 libjs-handlebars.runtime 升级至 4.7.9-1 及以上版本
5. 将组件 handlebars 升级至 4.7.9-1 及以上版本

## Linux Copy Fail 本地提权漏洞 (CVE-2026-31431)

- **CVE编号:** CVE-2026-31431
- **危害定级:** 高危
- **漏洞标签:** 漏洞武器化
- **披露日期:** 2026-04-22
- **信息来源:** [https://avd.aliyun.com/detail?id=AVD-2026-31431](https://avd.aliyun.com/detail?id=AVD-2026-31431)

### 漏洞描述

Linux kernel 是开源操作系统内核，2026年4月，互联网上披露 CVE-2026-31431 Linux Copy Fail 本地提权漏洞。由于Linux 内核加密子系统 authencesn模块中存在逻辑缺陷，攻击者通过 AF_ALG 套接字暴露的内核加密 API，配合 splice()系统调用，可实现对 setuid 二进制文件（如 /usr/bin/su）页缓存的 4 字节任意写入，并最终导致本地提权。

### 修复方案

1. Linux内核官方已在 commit a664bf3d603d 中发布安全更新补丁。
2. 针对已经正式发布安全版本及其补丁各 Linux 发行版（Ubuntu. RHEL. SUSE 等），云安全中心漏洞管理已经持续跟进并第一时间上线检测与修复规则。
3. 云安全中心恶意脚本检测已支持对目前披露的漏洞利用POC进行落盘文件告警。
4. 主机缓解措施：注该缓解措施不适用所有的linux发行版，部分发行版内核（例如 Centos 8.5 ）静态编译了相关模块，导致实际无法禁用。
Step1 潜在影响排查：例如排查是否存在启用了 afalg的 OpenSSL. 直接绑定 aead/skcipher/hash socket 的进程应用等。可通过以下命令排查当前系统上是否有进程使用 AF_ALG
lsof | grep AF_ALG
ss -xa
Step 2 禁用 algif_aead模块：在确认无进程应用使用AF_ALG 后可执行以下命令以禁用 algif_aead模块，阻断漏洞利用路径，在执行命令前建议做好快照或者备份措施。
# 第一条命令永久禁用，重启后生效
echo "install algif_aead /bin/false" > /etc/modprobe.d/disable-algif.conf
# 立即卸载，当前会话生效
rmmod algif_aead 2>/dev/null || true
5. 容器沙箱环境缓解措：利用 seccomp 禁止容器内创建 AF_ALG socket ，以seccomp profile JSON 为例
{"defaultAction":"SCMP_ACT_ALLOW","syscalls":[{"names":["socket"],"action":"SCMP_ACT_ERRNO","errnoRet":1,"args":[{"index":0,"value":38,"op":"SCMP_CMP_EQ"}]}]}

## Apache Tomcat 集群加密拦截器绕过反序列化代码执行漏洞（CVE-2026-34486）

- **CVE编号:** CVE-2026-34486
- **危害定级:** 高危
- **披露日期:** 2026-04-10
- **信息来源:** [https://avd.aliyun.com/detail?id=AVD-2026-34486](https://avd.aliyun.com/detail?id=AVD-2026-34486)

### 漏洞描述

Apache Tomcat 是一个Java Web 应用服务器，由于官方在修复CVE-2026-29146时导致疏漏，引入了新的代码缺陷，导致未成功解密的集群消息继续进入后续处理流程，从而绕过加密保护，并且可以造成反序列化。因此在CVE-2026-34486中，攻击者在可访问到集群端口的情况下可构造恶意请求执行任意代码，控制服务器。官方已发布安全更新，建议升级至最新版本。

### 修复方案

1. 建议升级Tomcat至最新版本。
2. 若使用集群模式，请利用安全组设置集群监听端口（默认4000）仅对可信地址开放。

- **CVE编号:** CVE-2026-33017
- **危害定级:** 严重
- **漏洞标签:** 漏洞武器化
- **披露日期:** 2026-03-20
- **信息来源:** [https://avd.aliyun.com/detail?id=AVD-2026-33017](https://avd.aliyun.com/detail?id=AVD-2026-33017)

## Linux Copy Fail 本地提权漏洞 (CVE-2026-31431)

- **CVE编号:** CVE-2026-31431
- **危害定级:** 高危
- **漏洞标签:** 漏洞武器化
- **披露日期:** 2026-04-22
- **信息来源:** [https://avd.aliyun.com/detail?id=AVD-2026-31431](https://avd.aliyun.com/detail?id=AVD-2026-31431)

### 漏洞描述

Linux kernel 是开源操作系统内核，2026年4月，互联网上披露 CVE-2026-31431 Linux Copy Fail 本地提权漏洞。由于Linux 内核加密子系统 authencesn模块中存在逻辑缺陷，攻击者通过 AF_ALG 套接字暴露的内核加密 API，配合 splice()系统调用，可实现对 setuid 二进制文件（如 /usr/bin/su）页缓存的 4 字节任意写入，并最终导致本地提权。

### 修复方案

1. Linux内核官方已在 commit a664bf3d603d 中发布安全更新补丁。
2. 针对已经正式发布安全版本及其补丁各 Linux 发行版（Ubuntu. RHEL. SUSE 等），云安全中心漏洞管理已经持续跟进并第一时间上线检测与修复规则。
3. 云安全中心恶意脚本检测已支持对目前披露的漏洞利用POC进行落盘文件告警。
4. 主机缓解措施：注该缓解措施不适用所有的linux发行版，部分发行版内核（例如 Centos 8.5 ）静态编译了相关模块，导致实际无法禁用。
Step1 潜在影响排查：例如排查是否存在启用了 afalg的 OpenSSL. 直接绑定 aead/skcipher/hash socket 的进程应用等。可通过以下命令排查当前系统上是否有进程使用 AF_ALG
lsof | grep AF_ALG
ss -xa
Step 2 禁用 algif_aead模块：在确认无进程应用使用AF_ALG 后可执行以下命令以禁用 algif_aead模块，阻断漏洞利用路径，在执行命令前建议做好快照或者备份措施。
# 第一条命令永久禁用，重启后生效
echo "install algif_aead /bin/false" > /etc/modprobe.d/disable-algif.conf
# 立即卸载，当前会话生效
rmmod algif_aead 2>/dev/null || true
5. 容器沙箱环境缓解措：利用 seccomp 禁止容器内创建 AF_ALG socket ，以seccomp profile JSON 为例
{"defaultAction":"SCMP_ACT_ALLOW","syscalls":[{"names":["socket"],"action":"SCMP_ACT_ERRNO","errnoRet":1,"args":[{"index":0,"value":38,"op":"SCMP_CMP_EQ"}]}]}

## Apache Tomcat 集群加密拦截器绕过反序列化代码执行漏洞（CVE-2026-34486）

- **CVE编号:** CVE-2026-34486
- **危害定级:** 高危
- **披露日期:** 2026-04-10
- **信息来源:** [https://avd.aliyun.com/detail?id=AVD-2026-34486](https://avd.aliyun.com/detail?id=AVD-2026-34486)

### 漏洞描述

Apache Tomcat 是一个Java Web 应用服务器，由于官方在修复CVE-2026-29146时导致疏漏，引入了新的代码缺陷，导致未成功解密的集群消息继续进入后续处理流程，从而绕过加密保护，并且可以造成反序列化。因此在CVE-2026-34486中，攻击者在可访问到集群端口的情况下可构造恶意请求执行任意代码，控制服务器。官方已发布安全更新，建议升级至最新版本。

### 修复方案

1. 建议升级Tomcat至最新版本。
2. 若使用集群模式，请利用安全组设置集群监听端口（默认4000）仅对可信地址开放。

## Langflow public flow 远程代码执行漏洞（CVE-2026-33017）

- **CVE编号:** CVE-2026-33017
- **危害定级:** 严重
- **漏洞标签:** 漏洞武器化
- **披露日期:** 2026-03-20
- **信息来源:** [https://avd.aliyun.com/detail?id=AVD-2026-33017](https://avd.aliyun.com/detail?id=AVD-2026-33017)

### 漏洞描述

Langflow 是一个开源的 AI 工作流构建与部署工具，用于可视化创建和管理 AI Agent 及 LLM 应用。CVE-2026-33017 中由于 build_public_tmp 函数存在参数验证缺失问题，攻击者可在 POST 请求中传入包含任意 Python 代码的 data 参数，结合 AVD-2026-1867169 Langflow autologin 致 access_token 泄漏漏洞可在无需登录的情况下执行任意代码命令，控制服务器。

### 修复方案

1. 组件 langflow 升级至 1.9.0 及以上版本。
2. 利用安全组设置langflow仅对可信地址开放。
